# Stage 1 튜닝 설정

작성일: 2026-04-16

## 문제 진단

### 학습 로그 분석 (Gen 1~97)

| 구간 | AvgReward | 해석 |
|------|-----------|------|
| Gen 1~7 | **-1.0000** | 즉시 경계/지형 충돌 |
| Gen 8~97 | **-0.3000** | **타임아웃만 발생, 충돌 없음** — 제자리 맴돌기 학습됨 |

### 실제 스펙 (KoreaShipStats.asset 기준)

| 항목 | 값 |
|------|-----|
| maxSpeed | 500 |
| 실효 최대 속도 (깊은물 1.2배) | **600 m/s** |
| Spawn → Goal 직선거리 | ~66,000m |
| 직선 도달 소요 시간 | **110초** |
| maxEpisodeTime | 180초 (×1.6 여유, 충분) |

물리적으로는 이미 도달 가능한 환경. **문제는 보상 구조**.

### 근본 원인: "제자리 맴돌기"가 local optimum

스텝당 보상(기존):

| 행동 | 누적 보상 (180초 = 9000 스텝) |
|------|-------|
| 가만히 유지 (타임아웃) | -0.0002 × 9000 = **-1.8** + 타임아웃 -0.3 = **-2.1** |
| 전진 시도 중 충돌 | 전진 보상 소량 + 충돌 **-1** (즉시 종료) |
| 목표 도달 | 전진 보상 누적 + **+1** |

생존 패널티가 너무 약해서 "정지"의 기회비용이 불충분. 초기 랜덤 정책에서 충돌이 잦으면 에이전트는 "움직이지 않기"를 local optimum으로 학습.

## 튜닝 적용값

### ShipAgent.cs — 보상 계수만 수정

| 파라미터 | 기존 | 변경 | 근거 |
|----------|------|------|------|
| `maxEpisodeTime` | 180 | **180 유지** | 600m/s로 110초 도달, 1.6배 여유 |
| 생존 패널티 | -0.0002 | **-0.001** | 누적 -9 → "정지 = 최악" 명확 |
| 거리 보상 계수 | ×0.001 | **×0.005** | 스텝당 +0.05 vs -0.001, 신호/노이즈 50× |
| 방향 정렬 보상 | 0.0001 | **0.0005** | 초기 방향 잡기 강화 |
| 수심 품질 | 0.0001 | 0.0001 유지 | Stage 1 영향 미미 |
| 수로폭 품질 | 0.00005 | 0.00005 유지 | Stage 1 영향 미미 |

### 변경 불필요

- **`ShipStatsSO.cs` 기본값**: `.asset`에 `maxSpeed: 500`, `turnRate: 1`이 이미 설정됨 (Unity에서 .asset이 우선)
- **스폰 회전**: main의 `startFacingGoal=true + ±45° jitter` 구조가 이미 우수
- **하이퍼파라미터 YAML**: PPO 표준값 유지

9000 스텝 에피소드 기준:

| 시나리오 | 누적 전진 | 최종 보상 |
|----------|-----------|-----------|
| 제자리 유지 | 0 | **-9 (최악)** |

| 직선 골 도달 (110초, 5500 스텝) | ~330 | **+331 (최고)** |

"정지 = -9 / 움직이다 충돌 = +24 / 골 도달 = +331" — 전진을 확실히 선호.

## 학습 실행 후 관찰 지표

### 초반 30분 성공 신호
- `AvgReward`가 -0.3 → 양수 근접
- 첫 `GoalReached` 발생
- `BestReward`가 0에 근접 또는 양수

### 1시간 후에도 다음이면 재조정 필요
- `AvgReward < -0.5` 고정
- 충돌 비율 > 타임아웃 비율 (방향 제어 실패)
- `GoalReached == 0`
